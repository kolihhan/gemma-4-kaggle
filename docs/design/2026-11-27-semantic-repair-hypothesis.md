## Concept
Single 31B LlmAgent, native search/read/edit/command/status/submit loop remains the baseline. Hypothesize a compact explicit behavioral state, rather than a second mandatory model call or a new generic planner:
- requirement: issue-supported triggering conditions -> observable required outcome; distinguish explicit/inferred/unknown; preserve unaffected behavior;
- evidence: implementation/caller/test observations supporting each condition; unresolved evidence remains unknown;
- repair: map changed branches/data flow to the requirement; preserve a plausible patch, no mandatory rollback;
- check: targeted original-visible executable witness when available, else inspect code and admit uncertainty; bounded correction only on contradictory evidence.
This is a logical design, not hard enforcement. Avoid ritualized extra calls, arbitrary global cap reduction, or claiming a typed state just because text resembles JSON. Competition host is closed YAML compiler; response_schema is disallowed in generation config; custom host callbacks cannot be assumed available. Existing requirements skill, behavioral probe, multisurface and FORK are overlapping precedents; novelty/efficacy not established. If a new mechanism eventually warrants implementation, isolate it versus scored Champion, not cumulative prompt grafts. Any new stage must replace work within the same budget rather than silently add work.
