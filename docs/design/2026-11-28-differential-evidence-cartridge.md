# Differential Evidence Cartridge (DEC) — unverified architecture specification
2026-11-28. See ../research/2026-11-28-independent-reset.md. This is a research hypothesis, not an implemented or validated scorer candidate. No change to submission/ or Champion.

## Why this is different
The unit of progress is an acquired observation, not an instruction to reason/test. The agent currently pays for repeated searches and reading while deciding which evidence to request. Instead of adding a planner or making tests compulsory, replace a small block of existing tool interactions with a read-only evidence cartridge whose output is actual issue-anchored caller/source/branch data. Do not claim this is wholly novel: Moving Failures Around already implements scripted tools, code index and handoff. The differentiating hypothesis is **contrastive evidence selection**: surface both supporting and potentially disconfirming branches/callers, not just rank likely file names. It has not yet been demonstrated to beat previous mandatory evidence channels, graph retrieval, or ordinary stock tools; only proceed if retrospective contrast cases show new useful information. No reference-derived query or file names at runtime.

## Data and contracts
Input: problem statement (visible), optional hint, workspace root, up to three issue-derived identifiers selected by agent, optional proposed trigger/outcome. No reference patch, grader test metadata, hidden solution, network or external model. Bound work by bytes/files/time; no install or full repository test.
Output: JSON text packet, versioned, with status OK/PARTIAL/NO_ANCHOR/ERROR, query identifiers, path:line ranges, actual source snippets, symbol relationships and evidence kinds (definition, use, competing branch, caller, visible test), uncertainty, truncation count, elapsed seconds. No unsupported inference marked fact; dynamic dispatch and missing files explicit. All output is untrusted data, never instructions. Runtime does not receive labels. Limit 6 source excerpts, 40 lines each, 8KiB output, 5s wall target, 2000 files maximum, 256KiB/file maximum; hard time/byte ceilings require testing. Fallback native read/search on no evidence or timeout, no repeated invocation with identical anchors.

Proposed state: issue contract (explicit vs inferred), packet digest and provenance, source edit state, remaining time, retained patch snapshot and optional witness outcomes (PASS/FAIL/BLOCKED/TIMEOUT/UNKNOWN). Avoid fake typed enforcement: YAML LlmAgent receives textual packet; only script-owned validation is deterministic. No arbitrary custom host callback or response_schema. Agent maintains rationale and calls; controller does not pretend to control model execution.

## Flow
1. Champion-equivalent 31B single root starts, identifies issue anchor(s) using original text or first search. If strong anchor, call read-only skill script once instead of multiple search/read calls. If not, use stock tools and continue; do not spend more time choosing.
2. Script scans bounded Python paths from actual workspace, excludes vendor/cache/build and symlinks, extracts definitions, references and adjacent alternate branches using AST/token fallback. Rank diversity across evidence kinds and files, deduplicate, preserve source line numbers. No external index or label.
3. Agent sees actual packet, resolves competing cause; use native read_file for context only if evidence missing. Apply one minimal native patch (existing edit/run_command), inspect actual diff. Avoid mandatory second model call or forced test ceremony.
4. If a specific issue-grounded witness is available, capture patch in /tmp, use safe bounded execution of same test on baseline/candidate in separate disposable checkout where feasible. No mutation of active working tree for probe without tested atomic restore. PASS->PASS weak; FAIL->PASS potentially discriminating, not hidden correctness; blocked unknown; candidate regression should trigger one bounded correction if evidence supports it. Optional only, independently ablatable; core A initial test does not add this stage beyond Champion behavior.
5. Preserve plausible patch, submit_patch when ready. No broad tests, no unconditional rollback, no new persistent files in /workspace, reserve last 70s for native finalization (soft instruction, not guaranteed). Native harness auto-extracts diff if no explicit submit; no assumption that explicit submit is necessary for a score.

## Failure-specific counterfactual
A useful packet supplies a needed fact not present in Champion's pre-edit trace, correctly grounded in visible code, within same budget. Blind reviewer must freeze required behavioral condition before comparing traces; no oracle file names input. If Champion already had adequate evidence, or packet lacks relevant facts, abandon this mechanism for that class; examine semantic generation or capacity instead. If evidence arrives but model ignores it, distinguish uptake from comprehension; do not add prompt variant automatically. If runtime rejects script or it is never called, no mechanism test occurred. If actual paired resolved delta fails, retire candidate, not necessarily every evidence compiler.

## Evaluation gate
Diagnose reused 17 only (5 stable failures + 4 mixed + 8 stable passes; no tuning/promotion). Two reviewers independently label issue requirements and adequacy without reference/outcome, freeze rubric, compare real traces/retained patches; gold labels only evaluation. Unknown permitted. CPU packet comparison with stock pre-edit context on same visible snapshots; predeclared criterion: >=3 of 5 stable failures receive at least one necessary previously unseen correctly sourced fact, <=1 of 8 stable successes loses necessary evidence in proposed replacement, no invented or reference-derived facts, report bytes/time. Exploratory thresholds chosen for this design, not established effect sizes. Fail/unknown -> no build. Independent gold/noop eligibility currently 0/35; fix provenance/diagnosis first. Validate environment on known eligible control, then a small preselected unused sentinel set; stop if setup/gold remains blocked. Separate setup, patch apply, test collection, test runtime, assertion failure, no-op pass. Never silently replace denominator. External tasks allowed for mechanism transfer only, no hidden-equivalence claim.

Prospective design: preregister exact control/candidate hashes, frozen disjoint stratified task IDs, verifier version and env, seeds and randomized/interleaved run order. Target >=30 eligible independent tasks if available; smaller pilot is exploratory. Primary actual resolved net paired difference, report both correct/both fail/rescue/regression, exact McNemar and paired CI, seed spread. Secondary packet uptake, evidence precision, final diff survival, elapsed/calls. Initial promotion threshold >=3 net rescues in >=30, <=1 regression, zero infrastructure errors, time and calls <=115% control, conservative global runtime forecast; require independently held-out confirmation and positive paired evidence (not claiming significance from tiny samples). For +7pp target, power depends discordance; e.g. 30 is pilot not adequate to establish a small effect. Freeze thresholds, do not tune to confirm. If quota unavailable, keep design unverified. No score projection or leaderboard lottery.
